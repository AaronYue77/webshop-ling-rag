# WebShop 输入与回答格式

用户直接用自然语言提问，可以带上用途、预算、颜色、材质、尺寸、设备型号或排除条件，也可以按上一轮展示的序号追问。网页会传入必要的对话上下文。

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 规划 | `question` 原问题、`questionId`、`context` 中的前一次搜索、商品序号及当前商品 | `plan` 包含搜索、详情或比较，及任务、预算、材质等必要条件、排除条件和所指商品 |
| 检索 | 模型计划和 WebShop 目录 | 候选编号、商品 ASIN、原始排序、分类、描述、快照价、规格与缺失字段 |
| 核选和回答 | 原问题、`questionId`、`catalog` 目录证据 JSON 字符串，含 `action`、`result_limit`、`products` 及模型规划中的 `required_terms`、`excluded_terms` | `paragraphs` 为自然正文，`selections` 为新搜索中经过核选的商品编号和证据原文 |
| 页面 | 正文与通过校验的商品 | 回答正文 → 证据标签 → 图片 → 可展开的目录依据 |

## 正文写法

通常写一到三个完整段落。先直接回答核心问题，再把商品特点、推荐理由或比较取舍写在一起。会影响选择的资料缺口集中说明一次。简单问题用一段即可。用户明确要求清单或多个步骤时，相关事实放在同一项里。

新搜索先在 Kaggle 按模型规划中的必要词和排除词校验目录证据，再由 Ling 按原问题逐件核对商品种类、材质、用途及其他硬条件。只产生一件合格候选时，就推荐一件并说明原因。目录证据校验后没有候选时，Kaggle 服务直接说明本次检索没有找到可确认的商品。详情和比较仍回答用户指明的商品，缺少的字段按商品说明。

## 推荐示例

> 我想买一双黑色男士皮鞋，请你推荐几双，并告诉我为什么。

下方是期望输出示例。假设检索的第 1 个候选是网面运动鞋，第 2 个是有皮革鞋面目录证据的 ECCO 乐福鞋。每项 `quote` 都必须能在该候选的目录内容里找到。

```json
{
  "paragraphs": [
    "这批候选里，我会推荐 ECCO 的黑色平头乐福鞋。目录写明它有黑色选项，鞋面使用皮革，套穿款也适合通勤或半正式场合。其余候选的资料不足以确认符合皮鞋要求，所以这里只推荐这一款。",
    "如果你告诉我常穿的尺码和预算，我可以继续帮你筛。目录价格只是快照，下单前还要核对当前售价、尺码和库存。"
  ],
  "selections": [
    {"position": 2, "quote": "full-grain ECCO leather"}
  ]
}
```

`position` 是本轮原始召回的编号。网页按 `selections` 的顺序重新生成展示序号，所以上例只展示 ECCO，并把它编号为第 1 款。对话导出仍记录原始两件召回商品及排序，引用只记录展示的商品。

| 问法 | 期望输出 |
| --- | --- |
| 推荐几件预算内的商品 | 先说符合条件的选择，再说明每款适合什么需求。预算只按有依据的目录价或规格价核对。 |
| 比较第一款和第三款 | 先回答最关心的差别，再解释差价或用途取舍。两款保留上一轮的编号。 |
| 第三款是什么材质，39 码能买到吗？ | 连贯写出已知材质和尺码记录，区分尺码表、可选规格与实时库存。 |
| 推荐有某个接口的配件，别推荐转接器 | 按原问题核对接口、兼容型号和排除条件，无法从目录确认兼容性时说明。 |

接口会校验输出结构、候选编号和引句归属。商品与问题的语义匹配由 Kaggle 上的模型判断。推理协议为 `4`，需用与网页配套的 [Kaggle 推理 Notebook](../kaggle/webshop-ling-inference.ipynb)。
